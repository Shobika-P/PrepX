# PrepX — AI Campus Companion

PrepX is an existing React/Vite and Flask application for student-owned academic records, career skill-gap analysis, rule-based recommendations, and printable reports.

## Current behavior and data

- Accounts are created through the sign-up flow. Student names, records, and passwords are not seeded or shared between accounts.
- Passwords are stored as Werkzeug password hashes. Private profile, academic, skill, recommendation, and report requests require the account's bearer token and are restricted to that account.
- Students can enter subject names and marks during onboarding and can edit academic details and skills from the profile editor. Missing marks and attendance remain unreported; the app does not fill them with example values.
- Skill readiness is a weighted match: 75% core-skill coverage and 25% advanced-skill coverage. Role requirements are listed in `backend/database/seed_data.py`. Recommendations are generated by local rules, not an external AI service.
- Academic average is the arithmetic mean of available subject marks. Weighted GPA is the credit-weighted mean of grade points using the thresholds in `backend/services/academic_service.py`.

## Database requirement

MongoDB is the configured persistent database (`MONGO_URI`, `DB_NAME`). Career-role definitions are seeded automatically, but student accounts are never seeded. When MongoDB is unreachable, the current development fallback is `mongomock`, which is **in-memory only**: accounts and profile changes are lost when the backend process stops. The health response identifies this as a non-persistent fallback. Do not use that mode for real student records; start MongoDB and verify `persistent_storage: true` from `/api/health` first.

Example environment values for `backend/.env`:

```env
PORT=5000
DEBUG=False
MONGO_URI=mongodb://localhost:27017/campus_companion
DB_NAME=campus_companion
```

MongoDB is not bundled with this project and must be installed or provided separately. MongoDB was reachable on the inspected development machine; verify `/api/health` reports `persistent_storage: true` in the environment where you run the app. The temporary fallback remains for local UI/API development only.

## Run locally

Backend (from `backend/`):

```bash
python -m pip install -r requirements.txt
python app.py
```

Frontend (from `frontend/`):

```bash
npm install
npm run dev
```

Set `VITE_API_BASE_URL` if the backend API is not at `http://localhost:5000/api`.

## Verify

From the project root:

```bash
python -m pytest backend/tests -q
```

Frontend production build:

```bash
cd frontend
npm run build
```

## API overview

- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `PUT /api/auth/profile`
- `GET /api/academic/audit/<student_id>`
- `GET /api/skills/gap-analysis/<student_id>?role=<role_id>`
- `GET /api/recommendations/<student_id>?role=<role_id>`
- `GET /api/reports/student/<student_id>?role=<role_id>`
- `GET /api/careers/roles`, `GET /api/health`

All profile and analysis endpoints require `Authorization: Bearer <token>`. The API rejects attempts to use one account's token with another student's ID.
